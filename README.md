Домашня робота до тем 3 та 4: рекурсія і сортування.

Структура проєкту

task_1.py — рекурсивне копіювання й сортування файлів за розширеннями.

task_2.py — рекурсивна візуалізація фрактала «сніжинка Коха».

task_3.py — порівняння сортування злиттям, вставками та Timsort.

Усі програми використовують лише стандартну бібліотеку Python.

Завдання 1. Рекурсивне сортування файлів

Програма рекурсивно обходить вихідну директорію, копіює всі файлидо цільової директорії та розподіляє їх у піддиректорії за розширенням.

Наприклад:

dist/
├── jpg/
├── pdf/
├── py/
├── txt/
└── no_extension/

Файли без розширення потрапляють до папки no_extension.Якщо трапляються файли з однаковою назвою, програма додає до назвичисловий суфікс і не перезаписує вже скопійований файл.

Запуск

python task_1.py path/to/source

Другий аргумент необов'язковий. За замовчуванням результат зберігаєтьсяв директорії dist.

python task_1.py path/to/source path/to/destination

Приклад

python task_1.py ./source_files ./dist

Завдання 2. Сніжинка Коха

Програма рекурсивно малює фрактал «сніжинка Коха» за допомогоюмодуля turtle. Користувач може вказати рівень рекурсії.

Запуск з інтерактивним введенням

python task_2.py

Запуск із рівнем рекурсії в командному рядку

python task_2.py 3

Також можна змінити довжину сторони:

python task_2.py 4 --size 500

Рівні 0–4 відображаються швидко. На вищих рівнях кількістьрекурсивних викликів і час малювання суттєво зростають.

Завдання 3. Порівняння алгоритмів сортування

У програмі порівнюються:

Сортування злиттям — власна реалізація.

Сортування вставками — власна реалізація.

Timsort — вбудована функція Python sorted().

Для вимірювання часу використовується модуль timeit.Алгоритми тестуються на трьох типах даних:

випадкові;

вже відсортовані;

відсортовані у зворотному порядку.

Запуск

python task_3.py

Власні розміри наборів і кількість повторень:

python task_3.py --sizes 100 500 1000 2000 --repeat 5

Час залежить від комп'ютера, тому важливе не конкретне число секунд,а співвідношення результатів між алгоритмами.

Сортування вставками може бути швидким на невеликих або майжевідсортованих наборах, однак на випадкових і зворотно відсортованихданих його час швидко зростає через квадратичну складність.

Сортування злиттям демонструє стабільніше зростання часу для різнихтипів вхідних даних, що відповідає складності O(n log n). Водночасвласна реалізація Python має додаткові витрати на рекурсивні виклики,зрізи списків і створення проміжних списків.

Timsort знаходить уже впорядковані фрагменти даних, так звані runs,використовує сортування вставками для невеликих фрагментів і ефективнозливає більші відсортовані частини. Саме поєднання цих підходів дозволяєйому добре працювати як на випадкових, так і на частково або повністювпорядкованих даних.

Висновки

Емпіричне тестування підтверджує теоретичні оцінки складності:

час сортування вставками найпомітніше зростає зі збільшенням набору;

сортування злиттям масштабується значно краще за сортування вставками;

вбудований sorted() зазвичай є найшвидшим у всіх тестах;

перевага Timsort особливо помітна на вже впорядкованих даних;

для практичних задач доцільніше використовувати вбудовані алгоритмиPython, оскільки вони оптимізовані та реалізовані на нижчому рівні.

Отже, поєднання сортування вставками та злиттям разом із використаннямвже впорядкованих ділянок робить Timsort ефективнішим за окремінавчальні реалізації цих алгоритмів у більшості практичних випадків.
